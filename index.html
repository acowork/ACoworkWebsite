One platform for humans & AI agents to ship work together.

ACowork is a multi-user, distributed, AI-native collaboration platform. Declarative .agent packages, one Rust binary, standalone-to-cluster — same code path.

acowork@gateway: ~ 
# 1) Start the Gateway (cluster mode)
$ ./acowork-gateway \
      --addr            0.0.0.0:19876 \
      --mqtt-addr       0.0.0.0:19875 \
      --advertise-host  gw.lan

✓ Gateway     listening on  http://gw.lan:19876
✓ MQTT broker on              gw.lan:19875

# 2) On any host, enroll a Node into the cluster
$ ./acowork-node start \
      --gateway gw.lan:19875 \
      --token   $ENROLL_TOKEN

✓ enrolled as node-<uuid> · Runtime host ready

Features

What you get, out of the box.

Declarative agents

.agent packages — manifest + prompts + skills, no executable code, signed and verified at install time.

Universal runtime

One Rust binary loads any .agent. Agents talk to LLMs directly — no proxy, no extra latency.

Distributed by default

Gateway + Node + Runtime, one protocol path. Standalone, remote nodes, or relay — same binary, no branches.

AI-native PM & Doc

acowork-pm and acowork-doc as first-class services — REST + MCP, real-time multi-user editing.

Biomimetic memory

Per-agent Grafeo graph DB · 3-tier / 5-class layers · HNSW + BM25 hybrid retrieval.

Multi-tier permission system

Admin/user roles · per-node, per-agent, and per-session visibility with explicit user grants. Least privilege, by default.

A · Standalone

Local single host

Personal use, demos, edge devices. Gateway auto-spawns one local Node Agent. Zero setup.

C · Relay

NAT’d / remote access

Reach your home Gateway from anywhere with a thin WSS tunnel — no public port, no VPN. Layered on top of Standalone or Cluster.

Gateway · flip the tunnel on (no restart)
acowork@gateway: ~ 
$ curl -X POST http://127.0.0.1:19876/api/relay/enable \
      -H 'Content-Type: application/json' \
      -d '{"url": "wss://relay.example.com/tunnel"}'
✓ tunnel established · gw-id: 7f3a-…
acowork@gateway: ~ 
$ $body = '{"url": "wss://relay.example.com/tunnel"}'
$ curl.exe -X POST http://127.0.0.1:19876/api/relay/enable `
        -H "Content-Type: application/json" `
        -d $body
✓ tunnel established · gw-id: 7f3a-…

PowerShell's curl is an alias for Invoke-WebRequest — call curl.exe explicitly for the same behavior as bash.

acowork@gateway: ~ 
$ curl -X POST http://127.0.0.1:19876/api/relay/enable \
      -H 'Content-Type: application/json' \
      -d '{"url": "wss://relay.example.com/tunnel"}'
✓ tunnel established · gw-id: 7f3a-…
Node

Unchanged — Nodes still talk to the local Gateway as before. Relay only rewires the inbound path.

Desktop — Settings → Gateway tab → switch to Relay (WAN) → enter https://7f3a-….relay.example.com. · Mobile — same; ideal for on-the-go access to a home gateway.
