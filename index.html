Features

What you get, out of the box.

Declarative agents

.agent packages — manifest + prompts + skills, no executable code, signed and verified at install time.

Universal runtime

One Rust binary loads any .agent. Agents talk to LLMs directly — no proxy, no extra latency.

Distributed by default

Gateway + Node + Runtime, one protocol path. Standalone, remote nodes, or relay — same binary, no branches.

AI-native PM & Doc

acowork-pm and acowork-doc as first-class services — REST + MCP, real-time multi-user editing.

Biomimetic memory

Per-agent Grafeo graph DB · 3-tier / 5-class layers · HNSW + BM25 hybrid retrieval.

Multi-tier permission system

Admin/user roles · per-node, per-agent, and per-session visibility with explicit user grants. Least privilege, by default.

Get Started

Two ways to install. Three ways to deploy.

Pick how you want to run it — install a prebuilt binary, or build from source. Standalone, cluster, or relay — same binary either way.

Install a prebuilt binary

Drop acowork on your PATH in seconds — no Rust toolchain, no clone.

# macOS / Linux — one-line installer:
$ curl -fsSL https://acowork.dev/install.sh | sh

# Windows (PowerShell):
$ irm https://acowork.dev/install.ps1 | iex

# Or grab a release artifact directly:
#   https://github.com/acowork/ACowork/releases/latest

$ acowork --version
✓ acowork 0.x.y

# Launch a Standalone host — the easiest deployment:
$ acowork run standalone
✓ Gateway    listening on  http://127.0.0.1:19876
✓ MQTT       broker    on   127.0.0.1:19875
✓ Local Node Agent enrolled (uuid=local-…)
✓ Ready. Open Desktop App →  http://localhost:5173

Build from source

For contributors and packagers — builds the same binary the install script downloads.

$ git clone https://github.com/acowork/ACowork
$ cd ACowork

$ cargo build --release --workspace
… ~5 min on first build, cached after …

$ ./target/release/acowork --version
✓ acowork 0.x.y

# Launch a Standalone host from source:
$ ./target/release/acowork run standalone
✓ Gateway    listening on  http://127.0.0.1:19876
✓ MQTT       broker    on   127.0.0.1:19875
✓ Local Node Agent enrolled (uuid=local-…)
✓ Ready. Open Desktop App →  http://localhost:5173

Deployment topologies

Same binary. Three wirings.

Once installed, pick how your nodes connect — the binaries don't change.

A · Standalone

Local single host

Personal use, demos, edge devices. Gateway auto-spawns one local Node Agent. Zero setup.

$ acowork run standalone
✓ Gateway   listening on  http://127.0.0.1:19876
✓ Local Node Agent enrolled (uuid=local-…)
✓ Ready. Open Desktop App →  http://localhost:5173
B · Remote nodes

Cluster

Multiple machines, one Gateway. Run heavy agents on a GPU box, lightweight on a laptop — both enroll over MQTT.

# On every host that should host Runtimes
# (GPU box, workstation, cloud VM):
$ acowork-node \
      --gateway mqtts://gateway.example.com:19875 \
      --token   $ENROLL_TOKEN
✓ enrolled as node-

# Gateway discovers it automatically.
# Same protocol path; zero local-vs-remote code.
C · Relay

NAT'd / remote access

Reach your home Gateway from anywhere with a thin WSS tunnel — no public port, no VPN.

# Gateway side — flip the tunnel on:
$ acowork relay enable wss://relay.example.com/tunnel
✓ tunnel established · gw-id: 7f3a-…

# Desktop side — Settings → Connection: Relay
# URL: https://.relay.example.com
# Login with your normal account.
